# Agent TOML Implementation - Technical Deep Dive

## 1) Objective and implementation boundary

This document describes the implementation completed for a declarative multi-agent system driven by TOML definitions, with end-to-end changes in backend and frontend.

Implementation target achieved:

- Per-athlete declarative agent system persisted by athlete_id.
- Runtime builder that compiles TOML into ADK agents.
- CRUD + validate API for the definition file.
- React Flow designer that edits and persists the full graph.
- Runtime integration in chat and wiki-chat flows.
- Optimistic locking and conflict path (HTTP 409).
- Firestore primary storage with local JSON fallback.

This is implementation documentation (what is in code now), not a future design proposal.

---

## 2) High-level architecture after implementation

Request path now works as follows:

1. Frontend designer loads athlete definition from API.
2. User edits graph + metadata in React Flow.
3. Frontend serializes graph -> TOML and validates via API.
4. Save uses versioned PUT; backend validates and persists.
5. Chat runtime builds orchestrator from athlete TOML at request time.
6. Wiki chat tries custom TOML-based wiki instruction first, then legacy prompt store fallback.

Core principle: runtime behavior is no longer hardcoded in agent/app.py; it is compiled from TOML through AgentDefinitionBuilder.

## 3) Backend implementation details

### 3.1 Core module: agent/builder.py

This file contains parser, semantic validator, storage abstraction, default template, and ADK builder.

#### 3.1.1 Constants and global config

- MAX_DEFINITION_AGENTS = 10
- WIKI_RESEARCH_CHAT_AGENT_ID = "wiki_research_chat"
- DEFAULT_COLLECTION = "agent_definition_file"
- SKILLS_DIR = agent/skills
- VALID_PLANNER_MODES = {"always", "full_only", "off"}
- AGENT_ID_RE = ^[a-z0-9_]+$

#### 3.1.2 TOML parser fallback for Python 3.10

- Uses tomllib when available.
- Falls back to tomli on ModuleNotFoundError.

This is why tomli was added to backend dependencies.

#### 3.1.3 Data contracts (dataclasses)

- AgentDefinitionEntry:
  - athlete_id
  - toml_content
  - version
  - updated_at
  - updated_by
  - is_default

- AgentConfig:
  - agent_id, name, description
  - instruction, skill
  - model
  - tools, sub_agents
  - planner, wiki_context

These contracts separate persisted definition payload from runtime-resolved agent config.

#### 3.1.4 Default TOML template

DEFAULT_TOML_TEMPLATE is generated by _build_default_toml_template().

Template characteristics:

- [system]
  - entrypoint = orchestrator
  - model = ""
  - planner_mode = full_only
- [[agents]] entries include:
  - intent_router (skill)
  - plan_react_planner (skill + planner=true)
  - strava_ingestion_agent (skill + run_ingestion_pipeline)
  - query_agent (skill + run_query_pipeline)
  - answer_agent (skill)
  - orchestrator (instruction + sub_agents)
  - wiki_research_chat (instruction + wiki_context=true)

The orchestrator instruction includes a runtime directive line that can be replaced at build time according to planner mode.

#### 3.1.5 Tool catalog (closed set)

TOOL_CATALOG maps TOML tool names to Python callables:

- run_ingestion_pipeline -> agent.tools.pipeline.run_ingestion_pipeline
- run_query_pipeline -> agent.tools.pipeline.run_query_pipeline

Unknown tools are rejected by semantic validation.

#### 3.1.6 Storage layer: AgentDefinitionStore

Storage mode selection:

- Firestore mode if:
  - USE_FIRESTORE_STATE is truthy (1/true/yes/on)
  - firebase_admin and firestore import successfully
  - firebase app/client initializes correctly
- Else local mode.

Collection name:

- FIRESTORE_AGENT_DEFINITION_COLLECTION env var if set
- else DEFAULT_COLLECTION (agent_definition_file)

Local fallback file:

- <tempdir>/strava_agent_state/agent_definition_file.json

Store API behavior:

- get(athlete_id):
  - reads Firestore doc by athlete_id
  - on read failure, logs warning and switches to local mode
  - if no custom record exists, returns default_entry(is_default=true, version=0)

- save(... expected_version ...):
  - computes denormalized fields from parsed TOML:
    - entrypoint
    - agent_count
    - agent_ids
  - checks optimistic lock current_version == expected_version
  - on conflict raises AgentDefinitionConflictError with message:
    - Version conflict: expected {current_version}, got {expected_version}
  - increments version and persists payload
  - if Firestore save fails, logs warning and falls back to local mode

- delete(athlete_id):
  - deletes Firestore doc if available
  - on failure, falls back to local mode and removes local record

#### 3.1.7 Parsing + semantic validation

_parse_toml(toml_content):

- Parses TOML root table.
- Raises AgentDefinitionValidationError("Invalid TOML syntax: ...") on parse failure.
- Raises validation error if root is not a table.

_validate_definition(parsed) returns list[str] of semantic errors.

Validation rules implemented:

- [system] must exist.
- system.entrypoint required and non-empty string.
- system.planner_mode (if present) must be one of always/full_only/off.
- At least one [[agents]] entry required.
- Agent count max 10.
- Every [[agents]] entry must be a table.
- agent.id required.
- agent.id must match snake_case regex [a-z0-9_]+.
- No duplicate agent ids.
- agent.name required and non-empty string.
- Exactly one source field:
  - instruction xor skill
- skill must exist under agent/skills/<skill>/SKILL.md.
- tools must be array if present.
- each tool name must be non-empty string in TOOL_CATALOG.
- sub_agents must be array if present.
- each sub_agent must be non-empty string.
- planner must be boolean if present.
- wiki_context must be boolean if present.
- system.entrypoint must exist in agent id set.
- every sub_agent reference must target an existing agent.
- delegation graph must be acyclic.

Cycle detection implementation:

- DFS with color state map {0=unvisited,1=visiting,2=done}.
- Captures cycle path from first back-edge.
- Emits error: Delegation cycle detected: a -> b -> ... -> a.

#### 3.1.8 Runtime builder algorithm: AgentDefinitionBuilder.build_orchestrator

Inputs:

- athlete_id
- model_name override
- planner_mode runtime override

Algorithm:

1. Load definition entry:
   - if athlete_id missing/blank -> default_entry("default")
   - else store.get(athlete_id)
2. Parse + validate definition.
3. If custom definition invalid:
   - log warning with athlete id + errors
   - fallback to DEFAULT_TOML_TEMPLATE
   - re-parse + re-validate
4. Resolve system config:
   - entrypoint
   - system.model
   - system.planner_mode
   - runtime planner mode = normalize(planner_mode arg, fallback=system planner)
5. Build in-memory AgentConfig map.
6. Resolve active model precedence:
   - model_name arg (if non-empty) > system.model > env/provider default
7. Recursively compile each agent to LlmAgent with cache + cycle guard.
8. Return compiled entrypoint agent.

Per-agent compile details (_build_agent):

- tool_funcs resolved from TOOL_CATALOG.
- sub_agents compiled recursively and wrapped as AgentTool(agent=child).
- if runtime planner_mode == off:
  - planner-tagged child agents are removed from sub_agent list.
- instruction resolution:
  - skill -> load_skill_from_dir(...).instructions
  - else instruction string from TOML
- wiki_context injection:
  - prefixes WIKI_CONTEXT_BLOCK rendered with placeholders:
    - %%ATHLETE_ID%%
    - %%WIKI%% (empty string in this builder path)
- orchestrator runtime directive injection:
  - If agent_id == orchestrator, ensure/update line:
    - Runtime directive: <derived directive>
- effective model precedence for each agent:
  - agent.model > active_model
- planner kwargs:
  - if agent.planner and runtime mode != off and PlanReActPlanner import works:
    - planner=PlanReActPlanner()
- LlmAgent constructor compatibility:
  - first attempts with planner kwargs
  - on TypeError retries without planner kwargs

Planner directive mapping:

- always -> Always run plan_react_planner before delegation.
- full_only -> Run plan_react_planner only when intent_router outputs FULL_EXECUTION.
- off -> Do not run plan_react_planner.

#### 3.1.9 Wiki custom instruction resolver

resolve_wiki_chat_instruction_from_custom_definition(...):

- loads athlete definition
- ignores default definition (returns None)
- parse + validate custom TOML
- looks up target agent (default wiki_research_chat)
- requires wiki_context=true in that agent
- resolves instruction from skill or inline instruction
- returns string or None on any failure

This enables wiki chat to prefer TOML-authored behavior only when explicitly configured.

### 3.7 API surface: strava_agent_sdk/flask/routes.py

- 500: unexpected failure

Note:

- athlete_id in /validate is route-required and checked for non-empty.

#### 4.2.2 TOML -> definition parse

parseTomlDefinition(tomlContent):

- parse with smol-toml parse()
- defensive coercion helpers:
  - isRecord
  - asString
  - asNumber
  - asStringArray (trim + unique)
- normalizes planner_mode fallback to full_only
- normalizes agent id to lowercase snake_case-like token via normalizeAgentId
- sourceType resolution:
  - if skill non-empty and instruction empty -> skill
  - else instruction
- loads optional candidate.ui.x/y into agent.ui
- if system.entrypoint missing and agents exist:
  - assigns first agent key as entrypoint fallback

#### 4.2.3 Definition -> graph compile

buildGraphFromDefinition(definition):

- Creates agent nodes:
  - type=agent
  - node data generated by createAgentNodeData
  - position from agent.ui when present
  - otherwise radial fallback layout around center
- Adds conversation node (type=conversation)
- Builds delegation edges from sub_agents
- Builds entrypoint edge from entrypoint agent -> conversation node

Visual semantics:

- delegation edges: border color stroke
- entrypoint edge: success color, dashed, non-deletable

#### 4.2.4 Graph -> TOML serialization

definitionToToml(definition, nodes):

- preserves agent order based on current node order, then fallback order
- stores agent positions from nodes into ui.x/ui.y (rounded to 0.1)
- emits only meaningful optional fields:
  - description if non-empty
  - skill or instruction depending on sourceType
  - model if non-empty
  - tools if non-empty
  - sub_agents if non-empty
  - planner true only when true
  - wiki_context true only when true
- always emits system table with entrypoint/model/planner_mode
- stringifies using smol-toml stringify()

#### 4.2.5 Edge semantics and synchronization

- Connection rules:
  - agent -> conversation sets system.entrypoint
  - agent -> agent adds delegation edge if unique
  - source==target ignored
- collectSubAgentsFromEdges recomputes sub_agents map from edges
- useEffect sync updates definition.agents[*].sub_agents whenever edges change
- entrypoint edge is rebuilt as unique edge when entrypoint changes

#### 4.2.6 Editing behavior

Panel capabilities:

- edit system.entrypoint, planner_mode, system.model
- add agent (auto id agent_n, default instruction source)
- delete selected agent
- edit selected agent:
  - name, description
  - source type switch instruction/skill
  - instruction textarea or skill input
  - model override
  - tools CSV parser
  - planner checkbox
  - wiki_context checkbox

UX constraints:

- max agents enforced at 10 with user-visible error
- selected node synchronized with selectedAgentId from parent
- modal keyboard close on Escape

#### 4.2.7 API operations from designer

Load:

- GET /agent-definition/{athleteId}
- parse and render graph
- stores version and is_default flags

Validate:

- POST /agent-definition/{athleteId}/validate with toml_content
- success -> notice
- failure -> joined backend errors in UI

Save:

- validates TOML first
- PUT /agent-definition/{athleteId} with:
  - toml_content
  - version
- on success:
  - updates local version from response (or +1 fallback)
  - marks as non-default

Reload:

- re-fetches from backend and discards local edits

Restore default:

- DELETE /agent-definition/{athleteId}
- re-fetches resulting default definition

Auth header:

- includes X-Internal-Token when available from env

## 6) TOML schema as implemented

System table:

- entrypoint: required
- model: optional (empty means provider/env fallback)
- planner_mode: always | full_only | off

Agents array:

- id: required snake_case token
- name: required non-empty string
- description: optional
- instruction OR skill: exactly one required
- model: optional
- tools: optional array, must belong to backend catalog
- sub_agents: optional array of valid existing ids
- planner: optional bool
- wiki_context: optional bool
- ui.x/ui.y: optional frontend layout metadata

Backend ignores ui for runtime behavior and only consumes functional fields.

---

## 7) Planner mode precedence and effects

Precedence:

- Runtime planner_mode argument (chat request path)
- then TOML system.planner_mode
- then full_only default

Runtime effects:

- orchestrator runtime directive line is inserted/replaced in orchestrator instruction
- if mode=off:
  - planner-tagged sub-agents are removed from delegation lists
  - planner kwargs disabled for agent construction

## 8) Persistence and fallback behavior

Primary: Firestore

- collection configurable by env
- document id = athlete_id string

Fallback: local JSON state file in temp directory

Fallback triggers:

- Firestore init failure
- Firestore read/write/delete exceptions

Behavior guarantees:

- API still functions in local mode.
- Default template always available even with empty storage.

## 9) Validation and error mapping matrix

Backend validation origin and HTTP mapping:

- Request field issues -> route-level 400
- TOML syntax/semantic invalid -> ValidationError -> 400
- Version mismatch -> ConflictError -> 409
- Unauthorized internal token -> 401
- Unexpected exceptions -> 500

Representative error messages in implementation:

- Invalid TOML syntax: ...
- Field 'system.entrypoint' is required.
- Agent 'x' must have either 'instruction' or 'skill'
- Agent 'x' cannot have both 'instruction' and 'skill'
- Agent 'x' references unknown skill 'y'
- Agent 'x' references unknown tool 'z'
- Entrypoint 'x' not found in agents list
- Delegation cycle detected: ...
- Definition exceeds max agents: N > 10.
- Version conflict: expected A, got B

## 14) Known limitations in current implementation

- Tool catalog is static in code (no dynamic plugin registration from TOML).
- Planner suppression in off mode is based on planner=true flag on child agents.
- No history/audit trail per definition version beyond latest stored row.
- No explicit schema version field in TOML payload.
- Frontend parser normalizes ids aggressively; backend remains source of truth for final validation.
